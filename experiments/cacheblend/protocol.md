## Frozen pilot

40 records: first 20 MuSiQue and first 20 2WikiMQA records in the pinned release's inputs/musique_s.json and inputs/wikimqa_s.json, no exclusions. User confirmed downloading both publicly accessible JSON files (~8.5 MB) before download. No login or external dataset package required. These are the release's prepared retrieval contexts, not a recreated retrieval index or a newly sampled original benchmark split. Original item IDs/split provenance are absent; record index plus file hash is the identifier. Nested 2Wiki answer lists are flattened without changing strings.

Two configurations fixed before inference: first 4 or first 8 supplied retrieved contexts, up to 128 Qwen tokens each; all available contexts if fewer. Preserve source ordering, truncate at 128 without answer-aware cropping or additional retrieval. Passage labels and separators add tokens beyond 128; a separate first instruction chunk is included. Each input includes the same native nonthinking Qwen chat wrapper. Segment encoding uses add_special_tokens=False; wrapper is included once; token IDs are concatenated directly without decode/re-encode. The assembled IDs, decoded input, all raw source items, retained/omitted context counts and truncations are frozen in pilot.json. These shortened contexts may omit answers; gold quality describes this local pilot, not full paper workloads. Do not tune until a preferred gap appears. No replacement of weak items.

Greedy unrestricted generation, 32-token maximum, native EOS. Preserve outputs, generated IDs, gold EM and normalized word F1 (max over gold alternatives), truncation flags, exact generated-ID and normalized-answer agreement with full recomputation, initial next-token KL(full||method), TV and top-1 agreement. Raw complete decoded output is scored (no post-hoc extraction). Word F1 differs from release utils.py tokenizer-token F1, which unconditionally strips its assumed BOS and has a yes/no parser. No universal answer reliability implied. Work counts report QKV rows and attention/MLP rows separately and include fresh suffix plus refreshed early layers. They are not FLOPs or speedups. Local prefill times include custom copies, exclude independent prefill/model loading/generation; no SSD pipeline or serving throughput reproduced.

## Gates and phases

1. Independent chunk prefills with positions starting at zero. Compose by applying R(offset) to post-RoPE K; V unchanged. Fresh suffix never independently cached. Every method sees identical IDs.
2. On both fixed configurations of the first pilot item: compare first instruction chunk K/V across all layers; compare layer-0 K/V over all document positions; compare custom full logits and every K/V to native full; check native full/cache replay; compare custom naive to native suffix prefill; verify source cache unchanged and separate storage. Same retained atol=rtol=2e-4. CPU float64 is used only for divergence statistics; prior CPU/MPS discrepancy remains documented, no cross-backend equivalence claimed.
3. Evaluate full and naive on all 80 item/config pairs and review gold quality, coverage limitations, disagreement, divergence and completeness. Preserve failures, never drop or replace them.
4. Only after composition passes and baseline interpretation is documented, run reference V-HKVD adaptation at ratios 0, .16, .32. 0 is an explicit separate endpoint, not naive. Freeze ratios before results. Reference full-selection endpoint must match native full; selected rows and work retained. No oracle selections or full-cache transplant.

The release's flash-attention backend is unmodified and does not implement the fusion signature; selection lives in xformers.py. No claim to have run this original backend on MPS.

Naive endpoint: reuse all composed document KV at all layers, fresh suffix runs against it. Zero-selection endpoint: full document/suffix QKV at layers 0 and 1, full layer-0 attention/MLP; at layer 1 only suffix Q/attention/MLP survives; deeper document KV reused and suffix always recomputed. Thus its document work is nonzero. Full-selection endpoint: every row refreshed through custom executor, with complete causal attention, native norms and MLP. Cache snapshots and generation branches have independent storage.

## Numerical collection correction

The first milestone attempt failed an assistant-added raw-cache gate: first-layer shifted K differed by up to .000545 and five deep first-prefix V tensors failed the same mixed tolerance (worst .000694). Custom full/naive logits and complete KV matched native counterparts exactly, native cache replay passed, and ownership passed. Preserve this failed attempt in `artifacts/cacheblend/failed-milestone-1/`.

Diagnosis with identical local chunk shapes found offset-only rotation failing at larger offsets for large Qwen keys (layer-0 maximum magnitude ~350–390). Native-coefficient correction `R(global) R(local)^-1`, including division by native `cos²+sin²`, reduced the layer-0 correction error versus native globally positioned prefill to <=6.11e-5 in the first configuration. Deeper globally shifted prefills themselves drift because of accumulated floating-point attention differences. The corrected path therefore validates each layer's corrected key against applying native global RoPE directly to the captured local pre-RoPE key; it does not expect independently shifted deep *hidden states* to be identical in floating point.

The first-prefix deep V discrepancy also occurs between two native executions with identical prefix tokens and positions but different total attention shapes; it is not caused by concatenation or position correction. The revised milestone retains these raw tensor comparisons as explicit diagnostics, gates first-prefix next-token logits instead, and retains the unchanged 2e-4 absolute/relative tolerance throughout. This changes the assistant's initial collection gate; do not describe all raw tensors as numerically equivalent, or the collection procedure as unchanged after preregistration. Neither pilot membership, token IDs, scoring, decoding nor selection ratios changed.

Gold EM transitions are strict score changes, not manually adjudicated factual regressions. Whole-output F1 penalizes elaboration; complete raw answers are retained to distinguish formatting/instruction-following changes from factual changes. Two configurations reuse the same 40 items, so 80 pairs are not 80 independent questions. Charger state, power mode and thermal state were not controlled; timing observations cannot support a speedup claim.

At the check layer, the selected document count is `floor(document_length * ratio)`, including the cached instruction prefix in that denominator, matching the release's prefix-inclusive counting. The fresh suffix is appended separately and never competes for selection. Selection uses native `torch.topk`, then sorts positions; the release supplies no explicit tie policy. Exact selected indices are preserved, without inventing a cross-backend tie guarantee. “First chunk” in the native pilot checks is the initial instruction/chat-prefix cache chunk. The first document follows that prefix, so its deep cache is not expected to equal the full path merely because it is the first document.

The defined prompt is the direct assembly of segment-tokenized IDs. Segment boundaries may differ from tokenizing the decoded whole prompt in one call; no method retokenizes that text. Native full, naive and selective paths all receive the identical stored ID sequence. Full native forwards used to measure divergence are evaluation overhead and do not supply hidden states or caches to selection; selection uses only independently prefetched caches and its own execution.
