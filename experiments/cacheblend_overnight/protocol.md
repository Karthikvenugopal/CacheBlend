# One bounded overnight evidence-controlled diagnostic

Authorized explicitly by the user, including new manual evidence-chain annotations after the cached schema was found to lack official support annotations. This is separate from the committed 400-output pilot and closed edit-repair archives, which remain immutable. No selector changes, model downloads, services, cloud jobs, further sweeps, commits, pushes or publication.

Frozen inputs are in frozen.json. Candidate pool: indices20–39 of each cached release file, disjoint from the prior pilot. At most five qualified items per workload, ten total. Every included item has two manually quoted reasoning claims with context indices and character offsets; gold-string presence alone is never qualification. Ambiguous rubrics and incomplete or unanchored reasoning chains are excluded with reasons. Later Wiki candidates after the five-item cap are explicitly not qualified or evaluated. The set was chosen without inspecting any model outputs for those IDs. All provided text windows remain byte-for-byte intact; these may themselves be preprocessed/truncated portions of original articles. No original-article reconstruction or claim of ranked retrieval is made.

One configuration: exactly two whole cached text windows in supplied order plus the instruction prefix; <=1536 assembled prompt tokens. Two required windows, or one required and one additional fixed window, retaining unrelated text/distractors inside the windows. All assembled IDs, original records, retained/omitted indices and annotations are frozen before inference. Reference prompt wording and first-letter/question-mark normalization are retained inside a single native Qwen nonthinking wrapper. The five method labels, ratios0/.16/.32, max output128 tokens including EOS, greedy decoding, seed17, precision, model revision and method SHA are fixed. No extra answer extraction, aliases, retries of truncated outputs or workload modifications after preflight.

Model execution uses the unchanged experiments/cacheblend/core.py and cached Qwen3-1.7B revision70d244cc86ccca08cf5af4e1e306ecf908b1ad5e, MPS float32/eager. Native local/global RoPE coefficients, full fresh question suffix, independent branches, model/input identity, source-cache immutability and absolute-position masks are preserved. Zero selection refreshes early layers as previously documented. It is not naive reuse. Source code/model file digests are checked at startup. All selected rows and work counts are retained; no clean-cache transplant.

Preflight is the longest frozen prompt, Wiki25 (1356 tokens). It computes all five methods once; its completed results are retained as part of the ten-item evaluation. Gates at unchanged atol=rtol=2e-4: correction against native pre-RoPE keys; first-layer cache and first-prefix logits; custom full and reference ratio1 logits/all KV against native; native full/replay; native suffix/custom naive; all finite outputs; independent storage and unchanged source cache. Deep native prefix tensor differences remain explicit diagnostics as in the previous validated procedure, without relaxing any tolerance. Ratio1 is only an endpoint validation, not an additional generated evaluation method.

A supervisor runs one worker/model process and collects memory_pressure -Q, kernel pressure where available, vm_stat swap/VM counters, process RSS, plus worker RSS high-water and MPS allocated/driver/recommended memory. The conservative comfort gates are frozen in frozen.json. Unknown required free/swap telemetry stops; severe pressure sustained30s stops. Comfort requires no kernel warning>=2, free percentage>=15%, <=128MiB new preflight swapouts, peak process RSS<=12GiB and observed MPS driver<=95% recommended memory. These counters overlap and are not summed. Severe is critical pressure>=4/free<=10%, or >256MiB rolling60s swapouts with warning pressure/free<=20%. Existing historical swap usage alone is not a failure. No power/thermal/memory-limit settings are changed.

The six-hour wall budget begins when the supervisor starts and includes model loading, preflight and inference. At5h59m a graceful stop is requested; an independent timer kills a stuck inference worker at6h. Stop on OOM, nonfinite outputs, numerical failure or sustained severe pressure. No automatic retries. Each complete item-method JSON is atomically replaced then flushed and fsynced immediately; partial generated IDs and a status report survive an interrupted method. Explicit restart requires --resume, the identical frozen/code hashes and remaining time from the original deadline; completed methods are skipped. Failed numerical/resource runs are not automatically resumed. caffeinate -i wraps only this supervisor command and exits with it; the worker also stops if its supervisor disappears. The OS thermal protections remain enabled.

Scoring: existing raw normalized word EM/F1; reference first-line/yes-no parsing and normalization with parsed-answer EM and Qwen token-overlap F1. The release has no EM metric; the added EM is identified. Qwen has no added BOS, so the primary adapted token F1 retains its first real token. Exact release-style `[1:]` token F1 is recorded only as a bug diagnostic. Empty parsing is handled safely; literal No*/Yes* parser behavior remains visible. No Mistral tokenizer assets are fetched. Full is an agreement reference, not an answer oracle. Reference parsers do not remove same-line elaboration. Entire generated outputs and truncation flags remain available.

Report all completions, missing results, failures and truncations. Means and paired item-level differences versus full and naive, with seed17/10000 paired bootstrap percentile intervals, are descriptive for ten manually controlled items and do not establish equivalence or population coverage. Initial next-token KL/TV and both answer/ID agreement are separate from gold quality. QKV and attention/MLP rows are work proxies, not FLOPs/speedups. Prefill timing includes copies/position logging, generation includes branch cloning, and independent chunk prefill/native reference/validation overhead is separated. The one largest-case preflight supplies a conservative runtime estimate multiplied by1.5 for remaining items; its validation overhead makes this conservative. No thermal-performance or serving-speedup reproduction is claimed.
