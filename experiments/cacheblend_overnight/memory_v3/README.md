# Single frozen-v2 memory preflight

User authorized implementing the memory proposal and exactly one bounded preflight on the longest frozen-v2 item, across all five methods. No remaining-item batch is authorized or reachable from this launcher. This directory is a new implementation version; original frozen inputs, executor, worker, and failed-preflight files remain untouched.

The input is `../review_v2/frozen-v2.json`, retaining the agent-created annotation provenance and all retained input IDs. The longest item is selected by assembled token length. No evidence truncation, new assets, cloud use, ratio adjustment, precision change, or numerical tolerance change is introduced.

Changes:

- Verify cached manifest hashes and model revision before loading. Construct an untied meta model, preserving both checkpoint embedding and output matrices, as in the original runtime. Materialize one parameter at a time on MPS; transfer/cast in 1024-row slices and verify exact equality to stored float32 values with bounded host scratch. No whole CPU float32 model or model-sized allocator warmup is used. Buffers and rotary aliases are placed on MPS. Preserve native generation configuration, deterministic seed17, float32/eager.
- Compute native full reference before source composition, serialize complete float32 K/V one layer at a time, and release its cache after the replay check. Compare each subsequent candidate against a single disk reference layer at a time. The custom full executor can operate without a source cache. Native naive validation also uses disk serialization, avoiding simultaneous native/custom candidates.
- Preallocate final source K/V buffers; copy corrected independent chunk rows directly into them. Rotation diagnostics retain local pre-RoPE keys on CPU and move one layer back to MPS for the original arithmetic/check. No global concatenation copy is required. Remove redundant old-row clones before allocating private concatenation results.
- Each method owns its result K/V. Verify storage independence, hand that private cache directly to its single greedy continuation, release it before the next method, and verify the immutable source digest after decode. Checkpoint each completed output atomically with fsync. Native replay consumes its already-private reference cache; native suffix validation clones the source.

All original numerical gates are retained at atol=rtol=2e-4: stored-weight equality (stronger exact check), position correction, first-prefix logits and layer0 K/V, full and ratio1 complete K/V/logit endpoints, native replay, native naive endpoint, source identity and immutability, storage isolation, and finite outputs. Native deep-prefix tensor differences remain explicit diagnostics, as before. Selection schedule, causal mask, fresh-suffix policy, scoring, ratios0/.16/.32, and 128-token maximum are unchanged.

The supervisor records OS pressure, system swap counters and process RSS every5 seconds; the worker records process high-water RSS and MPS allocated/driver/recommended counters every second plus phase events. These overlap and must not be summed. MPS maxima are sampled observations, not exact allocation high-water counters. System swap traffic includes other processes. Severe pressure follows the retained rolling60-second rule (>256MiB new swapouts plus warning/free<=20%, critical pressure>=4, or free<=10%); 30 seconds sustained causes a stop request, with a30-second cleanup deadline. The six-hour hard watchdog remains. Missing telemetry or sampler failure stops the run. `caffeinate` is bound to the worker lifetime. No automatic retries.

CPU tiny-model regression tests compare the original and revised paths for exact logits, every K/V tensor, selected positions and work counts across naive, full, zero, .16, .32 and ratio1, and verify source isolation after native decode. These are implementation checks, not empirical quality evidence.

The separately stored preservation manifest hashes original inputs, code and failed-run evidence before the preflight. Run artifacts and final headroom decision are under `artifacts/cacheblend_overnight/memory_v3`. A successful preflight would only be evidence about observed serial memory headroom under that system load; it would not authorize or launch the batch.
