# Two-gate feasibility pilot

Only this experiment is authorized. Existing CacheEngine and demonstration baselines remain unchanged. Model weights are the pinned, already cached TinyLlama checkpoint; CPU float32, eager attention, eval/inference mode, seed 17, four threads. No downloads or paid/cloud inference.

Gate 1 compares the unchanged suffix's first-layer attention head output, before output projection, with a native direct attention forward. Equal token lengths, unchanged suffix positions, fixed weights, unpadded batch one and original-clean metadata are required. No-edit compares every original row; edited queries are outside the fixed-Q formula. Tolerance: atol=rtol=2e-4; actual errors are reported. Near-total removal of old attention mass triggers direct row recomputation; a fallback fraction above 5% prevents advancement. Three alternating paired collection/native measurements are retained. Collection includes original prefill, hooks, copies and a required extra chunked QK pass for normalization statistics. Normalizers and the subtractive update use float64; model/Q/O/KV stay float32.

Gate 2 additionally requires the all-position sparse repair endpoint, fresh-question logits and short greedy continuations to match native recomputation. Every partial method repairs the changed token envelope plus two non-overlapping 16-token regions on a shared grid anchored at the actual edit end (32 extra tokens through all 22 layers). The question is freshly computed. Delta uses summed per-token head-output-change norms; attention-to-edit uses summed old first-layer attention mass; local uses the first two regions; random uses frozen seeds 17, 29 and 43. The edit-only reference has zero extra tokens. Full recomputation processes the complete edited prompt natively. No selector accesses an oracle cache, answer label or gold evidence position.

Development: eight questions over three distinct document edits. Held-out: 24 questions over eight distinct document edits; these questions are correlated within documents and must not be called 24 independent edits. Direct lookups, distant two-hop dependencies and answer-invariant edits are separate strata. All complete rendered prompts are retokenized independently; lengths and query seams must match and the frozen budget must fit. A short development fixture initially lacked enough downstream tokens: neutral context was added before freezing, and the partial initial run was retained. No held-out inference preceded that correction.

The method/config/source/data fingerprints are written to frozen.json only after development completes. The held-out command refuses changed source/config/data and refuses to overwrite an existing pilot. No tuning is allowed using its outcomes. The same frozen source can be used for subsequent explicitly labeled replications, not to silently replace the pilot.

Answer utility: a predefined expected phrase must occur without its competing answer. Report strict normalized short-answer matching separately, alongside raw text and token-limit flags. This conservative rule is not semantic judging. Teacher-forced expected/alternative log probabilities and next-token distribution errors are additional measures, not substitutes for factual utility. Keep original and edited full-model failures visible. The factual experiment is declared inconclusive below 80% clean old+new answer reliability overall OR within any question stratum; this threshold is an operational pilot gate, not a general reliability guarantee. Always report all cases and the clean-pair subset. Manually inspect original/full outputs to distinguish substantive factual errors from conservative phrase-matching failures (including numeric or wording equivalents). Such annotations must stay separate from the frozen automatic scores and cannot be used to tune selectors after held-out inference.

Timing: two complete repetitions per method with seeded shuffled method order per case; generation is actually repeated. Include tokenization, signal/selection, cache cloning, sparse forward, fresh question and greedy generation. Original prefill plus method-specific metadata collection are separately recorded and added for one-edit/one-query lifecycle cost. Do not hide preparation behind think time or assume amortization. Metadata collection has one measurement per method/case in Gate 2; Gate 1 provides repeated collection diagnostics. Scoring/oracle calculation and model loading are evaluation/setup costs excluded from response latency. Timings are CPU functional observations, not evidence of GPU performance or proportional token savings.

Decision: numerical failure requires investigation before Gate 2. Factual baseline failure makes answer-efficacy conclusions inconclusive. Distribution gains alone cannot establish useful repair. Examine delta versus old attention-to-edit/local/random at the same work, including costs and invariant-answer failures. Reject or revise a signal that adds cost without distinct evidence of utility; do not claim novelty from a successful pilot.
