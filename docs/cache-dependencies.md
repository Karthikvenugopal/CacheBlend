# Why unchanged text can have stale KV

At layer ℓ, each position's key and value are projections of the representation entering that layer. After a causal attention layer, that representation can incorporate all earlier tokens. Changing token e can therefore change later positions' K/V in higher layers even when those later token IDs and positions stay identical. The first layer's K/V are a useful exception: they are projected from local embeddings, before that layer's attention mixes context.

An identical token prefix has identical causal history, so its cache is reusable under the same model, positions and mask. The exact baseline finds the longest shared token prefix after independently tokenizing both **complete rendered prompts**, clones that prefix, sets suffix positions to `prefix..N-1`, and gives the model an all-visible padding mask of length N. Llama's causal mask restricts each query to its allowed prefix. No padding or batches are supported here.

The naive experiment recomputes the changed token envelope with its exact prefix. It splices in old suffix states, then recomputes the last prompt token to obtain logits. Reusing just K/V cannot recover that final hidden state or its logits. The unchanged suffix states still carry old contextual dependencies; last-token replay does not repair them. If there is no retained suffix before the last token, this particular experiment reduces to exact recomputation of the affected suffix. No-edit runs clone both the whole cache and the stored final logits.

Equal **token** lengths keep positions fixed. Character lengths and boundaries are not proxies for tokens: `playing` → `played` can invalidate a token starting before the edited characters. All ranges are zero-based and half-open, and include chat-template/special tokens. A length mismatch raises `UnsupportedEdit` in both reuse modes. Full recomputation accepts any nonempty prompt independently.

A Snapshot records prompt IDs, owned per-layer tensors, final next-token logits and engine identity. Every mutable DynamicCache is constructed from copies; returned snapshots and decode branches own independent storage. A frozen dataclass alone would not protect tensor contents. Tests check storage addresses, run-order independence and deliberate mutation isolation. Snapshots are process-local and must not be manually altered and then presented as exact originals.

CPU float32 eager attention uses `atol=2e-4, rtol=2e-4` for next-token logits: each element must satisfy `abs(a-b) <= atol + rtol*abs(b)`. Splitting matrix operations can introduce rounding differences. The integration checks observed maximum differences around 2.2e-5 on short edited prompts. These tolerances are functional gates, not a proof for all inputs or a claim of bitwise identity. Greedy continuation divergence fails the exact gate and retains same-prefix teacher-forced logits for investigation. MPS requires separate validation; it is unavailable in this execution process.

Useful agreement has several axes: next-token KL/total variation, logit differences, greedy trajectory agreement, and factual correctness of changed and unchanged answers. A greedy match can conceal distribution drift; different wording can still give the same fact. Small float32 KL values may round slightly negative and are clamped to zero. The initial CLI reports strict normalized short-answer matches as a formatting-sensitive check; the development note separately assesses the actual factual content.
